# Цикл улучшения системы историй

Рабочая инструкция для ассистента, которого владелец запускает улучшать промпты и память. Написана 18 сентября 2026 сессией Fable 5.1; исполнитель по умолчанию — Opus 5. Состояние на эту дату записано в разделе «Что проверено вживую»: сверяй его с кодом, а не наоборот.

## Цель

Система историй должна работать на любой модели, а не на одной. Ищем общие принципы промптов и памяти, которые поднимают результат у моделей класса Gemma 4 31B и не ломают остальные. Бесплатные размещённые модели служат для этого дешёвым полигоном; бот на них не работает.

Мера — `score` из `npm run eval`: доля верных ответов на фиксированные вопросы о памяти у худшей модели списка, отдельно для режимов `plain` и `sgr`. Устройство оценки, адаптера и дневных лимитов описано в [model-providers.md](model-providers.md).

## Что можно менять

- `local/prompt.ts` — правила рассказчика и сборка запроса.
- `local/memory.ts` — схема и инструкции извлечения фактов, режимы `plain` и `sgr`.
- `local/generation.ts` — только тексты и параметры сжатия; порядок проверок и атомарность записи памяти не трогать.
- Тесты к этим файлам, когда меняется поведение.

## Что менять нельзя

Правка любого пункта отсюда делает сравнение версий бессмысленным. Если кажется, что без неё не обойтись, остановись и напиши владельцу.

- `examples/memory-checks.ts`, `examples/*-probe.ts`, `examples/frozen/` — вопросы, ответы, сценарии и замороженные сцены. Ошибку в проверке опиши владельцу, не исправляй сам.
- `local/eval.ts`, `local/budget.ts`, значения лимитов в `.env.eval` — измеритель и предохранитель.
- Запрет провайдера `openai-compatible` для бота в `local/config.ts` и правила приватности из `AGENTS.md`. `.env`, `.env.eval`, `data/`, `backups/` не открывать; нужный факт из них получай кодом, который печатает булевы значения, числа и размеры.
- Промпт нельзя подгонять под известные вопросы: никаких упоминаний печатей, колоколов, шахмат, танцев и других деталей сценариев. Правило должно быть сформулировано для любой истории. Подгонка видна по тому, что растёт один сценарий, а остальные стоят.

## Один шаг цикла

1. `npm run eval -- usage`. Если до лимита канала осталось меньше одного прогона, закончи на сегодня.
2. Базовая линия: прогони eval на текущем коде, сохрани `--out` в каталог вне репозитория. Без базовой линии того же дня сравнивать не с чем: состав и поведение бесплатных моделей меняются.
3. Прочитай в `eval.json` поля `failedKeys` и `error` по каждой модели. Ищи то, что проваливают несколько моделей сразу: это кандидат в общий принцип. Провал одной модели записывай, но не чини промптом.
4. Сформулируй одну гипотезу одним предложением и сделай одну правку. Несколько правок за шаг не дают понять, какая сработала.
5. `npm test` и `npm run check` должны проходить.
6. Прогони eval с тем же списком моделей и сценариев.
7. Сравни с базовой линией. Правка принимается, если `score` вырос больше шума (см. ниже) и ни одна модель основной группы не упала. Принятую правку закоммить отдельным коммитом в рабочей ветке; отклонённую откати через `git checkout -- <файл>`.
8. Запиши шаг в `docs/improve-log.md`: дата, гипотеза, что изменено, числа до и после по моделям, решение. Отклонённые гипотезы записывай тоже: они экономят следующему исполнителю прогоны.

## Шум

Память генерируется при температуре 0.2, а OpenAI — при своей по умолчанию, поэтому два прогона одного кода дают разные числа. Разброс на `battle` измерен 18 сентября (запись в журнале): у `gpt-5.4-mini` до трёх вопросов из восьми между прогонами, у Gemma один, Ministral стабильна. Поэтому на одном сценарии сравнивай минимум три прогона на сторону. Улучшение меньше этого разброса улучшением не считается; спорный результат проверь повторным прогоном, а не объявляй победой.

## Модели

Основная группа, по ней принимаются решения:

```
openrouter:google/gemma-4-31b-it,mistral:ministral-14b-2512,openai:gpt-5.4-mini,claude:claude-haiku-4-5-20251001
```

Gemma здесь платная (`openrouter-paid`, лимит 600 000 токенов в день, около $0.20): бесплатная не исполняет схему и часами отвечает 429. Модель без навязанной схемы в основную группу не берём: её формат случаен, и шум перекрывает любую правку.

Контроль, в редкий полный прогон: `openrouter:deepseek/deepseek-v4-flash-0731:free`. Слабая модель для проверки ясности формулировок: `openrouter:liquid/lfm-2.5-2.6b:free`.

`score` сейчас считается как минимум по всем моделям из `--models`, без деления на группы. Поэтому контрольные и слабую модель запускай отдельной командой, иначе число покажет только самую слабую.

Замороженные сцены пишет `openrouter:deepseek/deepseek-v4-flash-0731:free` командой `npm run eval -- write`. Переписывать их заново нельзя без владельца: новая запись обнуляет все прежние сравнения.

## Что проверено вживую на 18 сентября 2026

- Ключи OpenRouter, OpenAI и Mistral в `.env.eval` приняты провайдерами. Дневной счётчик считает.
- OpenRouter: формат потока, отключение рассуждения (`reasoning.enabled=false`) на DeepSeek и Gemma, запись сцен сценария `battle`.
- OpenAI: `gpt-5.4-mini` отвечает, формат потока совпал с ожидаемым.
- Mistral: `ministral-14b-2512` отвечает. `mistral-large-2512` недоступна на плане Free (403), `mistral-small` и `mistral-medium` отвечали 429 даже на одиночный запрос.
- Cerebras: 402 на все модели, бесплатный доступ на аккаунте не включён. Не использовать.

- Полный `npm run eval` на `battle` проходит от записи сцен до `score`; первые числа в [improve-log.md](improve-log.md).
- Схема памяти исполняется провайдером в OpenAI, Mistral и платной Gemma на OpenRouter: с ней `plain` проходит у всех трёх.
- Claude CLI со схемой (`--json-schema`): Haiku 4.5 проходит `plain`. Сжатие со схемой занимает около двух минут, и `sgr` упирается в таймаут 300 секунд: это сбой скорости CLI, а не памяти.
- `sgr` не проходит ни у одной модели из-за проверки `quote`; разбор в журнале. Пока это не решено, решения принимаются по `plain`.

Не проверено: сценарии `chess` и `dance` (сцены для них не записаны), поведение при исчерпании лимита. Первый, кто это проверит, обновляет этот раздел.

## Приёмка на GPU

Бот работает на расцензуренной Gemma 4 31B Q6K на своём GPU; размещённые модели только полигон. Размещённая Gemma — оптимистичная замена: после снятия отказов и квантизации модель следует формату хуже. Правка считается принятой окончательно после `npm run memory:probe` на GPU через очередь запущенного бота. Аренда стоит денег, поэтому на GPU проверяется уже отобранное, раз в несколько шагов, и только по слову владельца. Взрослое содержание на размещённые API не отправляется никогда: сценарии полигона остаются чистыми.

## Когда остановиться и написать владельцу

- `budget_exceeded`, `unauthorized` или 402/403 от провайдера. Лимиты сам не поднимай, платные каналы не открывай.
- Три отклонённые гипотезы подряд: скорее всего, упор не в промпте, а в проверках, сценариях или схеме памяти, и это решение владельца.
- Нужна правка из раздела «Что менять нельзя».
- Проверка из `memory-checks.ts` выглядит ошибочной или двусмысленной.

В отчёте владельцу: что пробовал, числа до и после по моделям, что принято, что отклонено и почему, сколько запросов потрачено.
