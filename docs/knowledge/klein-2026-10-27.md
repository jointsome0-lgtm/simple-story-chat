## The graphs

`gpu/image-workflow-klein.json` and `gpu/image-workflow-klein-edit.json` were written in API format from the official
templates, `image_flux3_klein_distilled_t2i.json` and `image_flux3_klein_distilled_image_edit.json` in
Comfy-Org/workflow_templates, UI format, last changed at 369c1ed12496 on 2026-10-17.

- Kept: the three loaders and their files (UNETLoader `default`, CLIPLoader `flux3` on `default`, VAELoader), the
  CLIPTextEncode for the prompt, and the sampler at the values the templates expose: 16 steps, cfg 1, `euler`,
  `simple`, denoise 1, which are the model card's 16 steps without guidance. The t2i template's inner sampler says 15
  steps of `er_sde`, but its subgraph's own inputs, 16 and `euler`, are wired over them.
- The negative is ConditioningZeroOut of the positive, as in the Krea graph and in Klein's edit template; the t2i
  template encodes an empty text instead. At cfg 1 the negative is not sampled.
- Dropped: the prompt upsampler branch (TextGenerate with the 9B model, its system prompt, the switch and the previews),
  the bounding-box nodes, the ResolutionSelector, ImageCompare and the notes.
- Both sample an EmptyFlux2LatentImage at 1280x720, the Qwen frame graph's canvas; the node's step is 16, and 720 is a
  multiple of it.
- The edit graph feeds up to six LoadImage nodes, `reference-1.png` to `reference-6.png`, into ReferenceMultiLatent
  (comfy_extras/nodes_edit_model.py:34), as the Qwen edit graph has six slots; Klein takes ten. Its API inputs are
  `positive`, `negative`, `vae`, `resolution: "resize"`, `resolution.megapixels: 1.0` (the template's value) and
  `images.image0` to `images.image5`: `_expand_schema_for_dynamic` in comfy_api/latest/_io.py joins a dynamic input's
  parts with dots, and the Autogrow prefix `image` has no underscore. Its outputs are 0 positive, 1 negative and
  2 empty_latent; the sampler takes the first two. The template samples from the third, an empty latent of the first
  reference's size; ours samples from its own EmptyFlux2LatentImage, because `local/image-batch.ts` needs the sampler's
  latent to have a width and a height. Whether a canvas of another size than the first reference's changes Klein's edit
  is not known.

Each reference reaches the VAE at the size the node resizes it to, `scale = sqrt(megapixels * 1024 * 1024 / (w * h))`
and then Python's `round(w * scale)` and `round(h * scale)` (nodes_edit_model.py:72-77). `image-batch.ts` records that
size as `referenceSizes` (`referenceResize`), checked equal to Python's over 137061 sizes and three megapixel values;
a 720x1280 portrait goes in at 768x1365. The VAE then trims each side to its own multiple before encoding, as it does
any picture; that trim is not recorded.

The text encoder's template at v0.42.1 is `<|im_start|>user\n{}<|im_end|>\n<|im_start|>assistant\n` with no system
turn (comfy/text_encoders/qwen3vl.py:159), and `Flux3Tokenizer` right-pads the sequence to a multiple of 80 tokens with
id 151643 (flux.py:205-214). `local/tokenizer.ts` counts that padding into the conditioning, which the DiT attends to,
and not into the prompt.

For a later step: bounding boxes. `Flux3LayoutPrompt` (comfy_extras/nodes_flux.py:304) only appends a JSON table of the
boxes to the prompt text, so a layout is a prompt the harness could write itself.
