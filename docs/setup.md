# Настройка и первый тест

Сейчас используется локальный процесс на компьютере и обычный Telegram Bot API. Доступа к Telegram Serverless у аккаунта владельца пока нет. Устанавливать Telegram Desktop не требуется: бот доступен из обычного приложения на телефоне или Telegram Web.

## Подготовка

1. Создай обычного бота через `/newbot` у [BotFather](https://t.me/BotFather). Его токен храни только локально.
2. Скопируй `.env.example` в `.env` и выставь права `chmod 600 .env`.
3. Заполни `TELEGRAM_BOT_TOKEN` и `SIMPLE_CHAT_ALLOWED_USER_IDS`. Сначала добавь только свой числовой Telegram ID.
4. Установи Claude Code и авторизуйся своей подпиской через обычный вход CLI. Для выбранного подключения API-ключ не нужен.
5. Запусти `npm start` из корня проекта. Требуются Linux, Node 24.9+ и `flock`. Пока бот работает, компьютер должен быть включён.

`.env` читается при запуске; переменные окружения процесса имеют приоритет. После изменения настроек перезапусти бот.

После переименования в `simple-story-chat` переменные `SIMPLE_CHAT_*`, путь базы `data/simple-chat.sqlite` и SSH-алиас `simple-chat-vast` сохранены для совместимости с существующей конфигурацией.

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Секретный токен обычного бота |
| `SIMPLE_CHAT_ALLOWED_USER_IDS` | Числовые ID через запятую, без общего доступа |
| `SIMPLE_CHAT_OWNER_ID` | ID владельца, разрешившего читать свои сообщения для отладки; не разрешение читать других пользователей. Должен входить в список доступа. По нему бот помечает строки журнала как `actor: owner`, остальные получают `other` |
| `SIMPLE_CHAT_DB_PATH` | По умолчанию `data/simple-chat.sqlite`; можно выбрать локальный путь на компьютере или сервере |
| `SIMPLE_CHAT_PROVIDER` | `claude-code` или `llama-cpp` |
| `SIMPLE_CHAT_MODEL` | По умолчанию `claude-haiku-4-5-20251001` |
| `SIMPLE_CHAT_CONTEXT_TOKENS` | 65536, включая резерв под ответ; CLI использует консервативную оценку входа |
| `SIMPLE_CHAT_MAX_OUTPUT_TOKENS` | Максимум ответа, по умолчанию 4096 |
| `SIMPLE_CHAT_COMPACT_AT_TOKENS` | Порог автоматического сжатия входа: 44000 для llama.cpp, 54000 для Claude Code |
| `SIMPLE_CHAT_KEEP_SCENES` | Сколько последних сцен оставлять целиком, по умолчанию 4 |
| `SIMPLE_CHAT_API_KEY`, `SIMPLE_CHAT_BASE_URL` | Ключ и корневой адрес llama.cpp; для Claude Code пустые |
| `SIMPLE_CHAT_MODEL_TIMEOUT_MS` | Таймаут вызова модели через CLI или HTTP; по умолчанию 300000 мс, в GPU-примере 600000 мс |
| `SIMPLE_CHAT_TEMPERATURE` | Температура художественного ответа llama.cpp, по умолчанию 0.8 |

Для Gemma на арендованной карте предусмотрены [отдельный профиль `.env.gpu` и инструкция](gpu.md). Команда `npm run start:gpu` использует прежние настройки Telegram и базу, заменяя подключение модели. Сначала требуется подготовить сервер и пройти `npm run model:probe`.

Для запуска в фоне можно использовать tmux:

```sh
tmux new -s simple-story-chat-bot 'npm start'
# Отсоединиться: Ctrl+B, затем D.
# Вернуться: tmux attach -t simple-story-chat-bot
```

Если сессия уже создана, подключись к ней, не запускай второй экземпляр. `flock` также не позволяет двум процессам одновременно работать с одной базой. Остановка: Ctrl+C в сессии бота. Незавершённый ответ не повторяется автоматически, уже сохранённые сцены остаются.

Бот при запуске проверяет отсутствие webhook. Если webhook настроен, он останавливается; автоматически чужую конфигурацию не меняет. Не используй одновременно облачный обработчик и локальный polling. Команды `tgcloud` относятся к отдельному, пока незапущенному облачному черновику; читать или редактировать `.tgcloud/` вручную не нужно.

## Первый прогон

Открой своего бота по ссылке `https://t.me/<имя_бота>` и отправь `/start`. Нажми **Новый сид** и скопируй показанный пример либо напиши свой сид по образцу. Пришли все части, нажми **Сохранить сид**, затем **Начать новую историю**.

Проверь несколько продолжений: свободный текст, авторское указание, кнопку **Продолжить**. Затем открой **Чекпоинты**, выбери раннюю сцену и нажми **Продолжить отсюда**. Напиши другое действие. Через **Ветки** можно вернуться к исходной линии событий.

Удаление сида удаляет его вместе со всеми историями из библиотеки. Удаление ветки сохраняет другие ветки и их общие сцены. Уже отправленные сообщения Telegram эти действия не стирают.

Если ответ не доставлен, `/last` покажет сохранённую сцену без повторной генерации. `/cancel` отменяет текущий ввод, сжатие или генерацию. Перед продолжением при достижении порога входных токенов бот сжимает старые сцены в новый инкремент памяти, оставляя последние четыре сцены целиком. Порог и число сцен задаются переменными выше. Исходный сид не сжимается. Чекпоинты до и после сжатия позволяют продолжить с любого из этих состояний; все исходные сцены остаются в архиве.

Чтобы сжать раньше порога, отправь `/compact` или нажми **Сжать сейчас** в `/context`. Новая сцена при этом не создаётся. Последние четыре сцены остаются целиком, более ранние переходят в очередной инкремент памяти. Если несжатых сцен не больше четырёх, бот объяснит, что сжимать пока нечего. `/cancel` отменяет выполняющееся сжатие.

В начале нового ответа показываются использованная модель и приблизительный процент заполнения окна. `/context` открывает детали текущей ветки. Для старого чекпоинта открой **Чекпоинты → нужная сцена → Контекст**: размеры относятся к выбранному моменту, включая его сид, инкременты памяти и оставшиеся сцены. Нулевое число инкрементов означает, что сжатия ещё не было.

Кнопка **Модель** и команда `/model` показывают выбранное подключение. Для llama.cpp бот проверяет доступность сервера, название модели и размер окна без генерации текста. Время проверки показано отдельно: успешный ответ не гарантирует, что сервер останется доступен. Для Claude Code показана подписка и, если уже был ответ, время последнего успешного обращения. Старым сценам не присваивается название новой модели после переключения. Выбор провайдера остаётся в конфигурации владельца, кнопка его не меняет.

Длинный сид можно вставить одним или несколькими сообщениями: бот собирает их по порядку до нажатия **Сохранить сид**, в том числе если клиент разбил вставку на части. После каждой части бот показывает их количество и общий размер. Название и дата остаются первыми двумя непустыми строками; следующие сообщения дополняют описание через пустую строку. Черновик сохраняется при перезапуске и не переключается на прежнюю историю при открытии меню. `/cancel` отменяет ввод. Общий предел черновика — 256 КиБ текста. Текстовые Rich Messages тоже поддерживаются: абзацы, списки, таблицы и раскрывающиеся блоки.

В режиме **Новый сид** можно прикрепить файл `.txt` или `.md` в UTF-8. Отправь полный сид по [примеру](../examples/seed.txt) либо сначала название и дату текстом, затем файл с описанием. Подпись к файлу не используется; PDF и DOCX не поддерживаются. Файл добавляется одной частью, после него тоже нужно нажать **Сохранить сид**. Предел 256 КиБ проверяется по фактически полученным байтам; повреждённый или не полностью загруженный файл не меняет черновик. Вне режима ввода сида файлы не скачиваются и не используются как команды продолжения.

Измеренные счётчики последнего запроса включают вход вместе с кэшем и выход, в том числе внутренние рассуждения модели. Оценки восстановления помечены `≈`; они не выдаются за точное число токенов. Старые сцены без usage сохраняют доступ к оценке размера, но не к историческим измерениям. Лимит следующего ответа по умолчанию 4096 выходных токенов; настройка допускает от 256 до 8192. В промпте указан максимум 12 абзацев без минимального объёма, но это инструкция модели, не принудительное обрезание текста. Если модель сообщает достижение лимита токенов, бот сохраняет полученный текст и отдельно предупреждает об обрыве.

Сцены отправляются целиком через `sendRichMessage`, для которого Telegram допускает до 32768 символов UTF-8. Это ограничение Telegram в символах, отдельное от лимита генерации в токенах. Обычные сообщения меню через `sendMessage` допускают до 4096 символов. [Лимиты Rich Messages](https://core.telegram.org/bots/api#rich-message-limits), [sendMessage](https://core.telegram.org/bots/api#sendmessage).

## Передача тестеру

После нашего прогона подключаем выбранную Gemma, проверяем её работу и добавляем ID тестера в список доступа. Тестер получает ссылку на бота и нажимает Start. Ему не нужны исходники, токен бота или аккаунт GPU-сервиса. GPU-профиль использует проверенную Gemma 4 31B Q6_K; `/model` показывает модель и состояние аренды. Если GPU остановлена, тестер нажимает «Запустить GPU» и дожидается готовности. Обычное сообщение само аренду не запускает.

Если тестер ещё не в списке доступа, его личная команда `/start` сохраняет только ID и время запроса в закрытых метаданных базы (`access_requests`, не более 100 отправителей). Доступ автоматически не открывается. Остальные сообщения таких пользователей не сохраняются и не передаются модели. Администратор добавляет нужный ID в `.env` и перезапускает бота; после этого тестер снова открывает `/start` или `/menu`.

Истории тестера не открываем и не экспортируем для отладки. Он сам описывает проблему и при желании присылает выбранный отрывок. Библиотеку храним отдельно от публичного кода и резервируем на машине, где запущен бот.

## Повторяемый тест битвы

`npm run story:probe` создаёт отдельную синтетическую историю на модели из конфигурации. Выбор сценария: `--scenario battle`, `--scenario chess` или `--scenario dance`. Для Opus: `npm run story:probe -- --scenario chess --model claude-opus-5`. Для уже подготовленного GPU: `node --env-file=.env.gpu local/story-probe.ts --scenario chess`.

Каждый сценарий содержит 16 ходов, три ручных сжатия после седьмой, одиннадцатой и пятнадцатой сцен, продолжение после третьего сжатия и заключительный запрос о сохранённых фактах. Оригиналы, инкременты и метрики записываются в отдельный каталог `/tmp/simple-chat-<сценарий>-*`; путь выводится при запуске. База бота и Telegram в тесте не используются. Это проверка памяти на небольшой истории. Вместимость и кэш при входе около 59K токенов отдельно проверяет `npm run model:probe -- --long`; качество длинной истории эта проба не измеряет.

В отчёте нужно сверять память с самими сценами: время и цель приёма, расход ресурса, травму и лечение, передачу предмета, исполнение обещания, дату события и дату получения сведений, отменённый план и условия перемирия. Валидный JSON и ссылки на все сцены сами по себе не доказывают, что модель сохранила каждый факт.

Шахматный сценарий использует проверенные ходы партии Каспаров–Топалов 1999 года с вымышленными персонажами. [Источник PGN](https://en.chessbase.com/portals/all/2021/03/throwback-kasparov/kasparov-topalov.pgn), эталонные позиции в `examples/chess-reference.json`. Модель получает только очередной отрезок ходов, без полного эталона и готовой конечной позиции. Танцевальный сценарий использует авторские связки и вымышленный регламент конкурса; проверяются версии движений, статистика тренировок и исправление судейской оценки.

После остановившегося теста можно продолжить с сохранённой сцены: `npm run story:probe -- --scenario chess --resume /tmp/simple-chat-chess-XXXXXX`. Старый процесс должен завершиться. Провайдер и модель должны остаться прежними. Скрипт не генерирует сохранённые сцены повторно; незавершённый вызов выполняется заново. Для Claude Code можно явно задать `--effort medium`; изменение записывается в отчёт возобновления.
