# simple-story-chat

Интерактивные истории в Telegram: сид задаёт мир и персонажа, модель пишет сцену, пользователь отвечает действием, репликой или авторским указанием. Текст появляется постепенно и поддерживает Markdown. Каждая сцена начинается датой и временем внутри мира.

Первый прототип работает локально на Node 24 и SQLite. Модель первого прогона: Haiku через установленный Claude Code и подписку. Telegram Serverless пока недоступен аккаунту владельца, поэтому используется обычный Bot API. Дизайн и код Telegram-интерфейса подготовил Opus 5; концепт ранее обсуждался с Fable 5.1.

## Как попробовать

После настройки и запуска отправь боту `/start` или `/menu`.

1. Нажми **Новый сид**. Бот покажет пример: название, дата и время, затем описание мира и персонажа. Описание можно прислать одним или несколькими сообщениями.
2. Дождись приёма всех частей и нажми **Сохранить сид**, затем **Начать новую историю**.
3. Отвечай обычным текстом или нажимай **Продолжить**.
4. Кнопка **Чекпоинты** открывает сохранённые сцены. **Продолжить отсюда** создаёт новую ветку; дальнейший текст продолжает выбранный момент.
5. Через **Меню → Сиды** можно вернуться к другим историям и веткам. Удаление сида удаляет все его истории из библиотеки бота. Удаление ветки сохраняет остальные ветки. Перед удалением бот показывает подтверждение; уже отправленные сообщения Telegram остаются в чате.

Сцены сохраняются автоматически. `/last` повторно показывает последнюю сцену без вызова модели. `/cancel` отменяет ввод сида, генерацию или сжатие. При сбое доставки готовый ответ остаётся в базе; повторная доставка входящего события не запускает ещё один вызов модели.

В начале новой сцены показываются модель и приблизительный процент заполнения контекста. Кнопка **Модель** или `/model` открывает текущее подключение и результат проверки сервера. Подробные счётчики доступны по кнопке **Контекст** или `/context`: оценка следующего запроса, резерв под ответ и измеренные входные/выходные токены. Выходные токены могут включать внутренние рассуждения модели. Служебная строка не сохраняется как часть сцены и не передаётся обратно модели.

Команда `/compact` или кнопка **Сжать сейчас** в контексте запускает сжатие раньше автоматического порога. Последние четыре сцены остаются целиком, исходный текст сохраняется, новая сцена не создаётся.

У чекпоинта кнопка **Контекст** показывает размер сида, инкрементов памяти, их суммы и ещё не сжатых сцен именно в этой точке. Размер в UTF-8 байтах точный для сериализованных частей; токены с `≈` оцениваются как байты / 4 с округлением вверх. Это грубая оценка, а не токенизатор Haiku. Просмотр статистики не вызывает модель. Для старых сцен, где usage ещё не сохранялся, точные счётчики недоступны.

## Запуск и проверки

Нужны Linux, Node 24.9+, `flock`, установленный Claude Code с действующей авторизацией и токен обычного Telegram-бота.

```sh
cp -n .env.example .env
chmod 600 .env
# Заполни .env локально.
npm start
```

`npm test` проверяет сохранение, ветвление, удаление, изоляцию пользователей, повторные события, сбои потока и навигацию. `npm run check` проверяет синтаксис. Эти команды не вызывают Telegram или платную модель, тестовые данные создаются во временной папке.

Рабочий код находится в `local/`. `schema.js`, `handlers/` и остальные файлы `lib/` относятся к прежнему черновику Telegram Serverless; локальный бот использует только чистую логику библиотеки из `lib/library.js`. Облачный черновик не развёрнут. Репозиторий пока локальный, публикация не выполнена.

## Ограничения первого прогона

Перед передачей бота тестеру проверяем искусственные истории сами. Gemma 4 31B Heretic Q4_K_M и Q6_K тестировались на RTX 5090 32 GB; GPU-профиль настроен на Q6_K. Тестовая аренда завершена, экземпляр удалён. Проверен вход около 59K токенов при окне 65536; это не доказательство сохранения фактов на всём окне. [Измерения и отдельный профиль запуска](docs/gpu.md).

Сбои компакта ещё не устранены окончательно. Журнал ошибок и прогресс добавлены; повторная проверка на GPU с несколькими последовательными компактами остаётся незавершённой. Переключение между GPU-инстансами пока не реализовано.

Перед продолжением автоматически сжимаются старые сцены, если вход достигает порога `SIMPLE_CHAT_COMPACT_AT_TOKENS` (по умолчанию 44000 для llama.cpp и 54000 для Claude Code). Последние четыре сцены остаются целиком. Модель добавляет инкремент памяти с датами и ссылками на исходные сцены. JSON сохраняется как исходная запись; в запрос он входит как читаемый текст, построенный кодом без повторного пересказа. Сид и прежние инкременты сохраняются; до и после сжатия создаются чекпоинты. Оригиналы сцен не удаляются. Если память не прошла проверку или не уменьшила запрос, она не применяется.

Общее окно настроено на 65536 токенов вместе с ответом. Предварительная оценка использует последний измеренный вход той же ветки, модели и версии промпта. Без такого замера используются байты UTF-8 / 4 плюс резерв 4096. Это оценка: адаптер дополнительно проверяет фактический вход Claude в начале ответа, до показа текста. Если порог уже достигнут, он прерывает этот вызов и запускает сжатие. Обработка входа при этом уже могла начаться у провайдера. Сид, накопленная память или сохранённые целиком последние сцены могут заполнить окно сами: тогда бот останавливается, сохранив архив.

При подключении llama.cpp вход считается серверным токенизатором до генерации и до решения о сжатии. Просмотр `/context` по-прежнему не вызывает сервер модели и показывает оценки. Измерения предыдущего провайдера не калибруют запросы нового подключения.

Бот принимает обычный текст, текстовые Rich Messages и файлы `.txt` / `.md` в UTF-8. Формат сида: название, дата мира, описание. В файле можно прислать полный сид по [примеру](examples/seed.txt) или только описание, предварительно отправив название и дату отдельным сообщением. Подпись к файлу не используется. PDF и DOCX не поддерживаются.

Части сида накапливаются в черновике до нажатия **Сохранить сид**, между ними добавляются пустые строки. Черновик сохраняется при перезапуске; меню и кнопки продолжения не выводят из режима ввода. `/cancel` удаляет черновик. Общий предел черновика — 256 КиБ текста. Текстовые Rich Messages могут содержать абзацы, списки, таблицы и раскрывающиеся блоки; неподдерживаемые вложения и сложные объединённые ячейки отклоняются целиком. Ошибка чтения файла не добавляет его частично и не запускает модель.

Пока бот работает на компьютере, компьютер и процесс должны оставаться включёнными. После перезапуска библиотека сохраняется. Прерванная генерация сама не повторяется.

Для разработки памяти есть экспериментальный режим `SIMPLE_CHAT_MEMORY_MODE=sgr` и [фоновое сравнение с обычным компактом](docs/gpu.md#фоновое-сравнение-памяти). Пробы работают на синтетических сценах, уступают запросам пользователей и не продлевают работу GPU. По умолчанию бот использует `plain`.

## Приватность

У каждого разрешённого Telegram ID отдельная библиотека. Список доступа задаётся в `SIMPLE_CHAT_ALLOWED_USER_IDS`; пустой список не открывает бота всем. Бот принимает сообщения только в личных чатах.

Владелец разрешил читать свои сообщения этому боту для настройки и отладки. Его ID хранится только локально в `SIMPLE_CHAT_OWNER_ID`. Разрешение не распространяется на тестера и остальных пользователей из списка доступа. Тестер сам сообщает о проблемах и при желании присылает выбранный фрагмент; разработчики и помощники не открывают его истории для диагностики.

Бот хранит сообщения для продолжения и передаёт контекст выбранной модели. Данные и ключи не входят в публичный исходный код: `.env`, `data/`, базы, экспорты, резервные копии и логи исключены из Git. Технические логи содержат только статусы и коды ошибок, без сидов, сообщений и сырых ответов провайдера. Администратор машины технически имеет доступ к хранилищу; это не сквозное шифрование от владельца сервера.

[Telegram Bot API](https://core.telegram.org/bots/api), [потоковый вывод Claude Code](https://code.claude.com/docs/en/headless).
